# Wiki / RAG M3：设置与云端向量

日期：2026-11-27（北京时间）。承接 [M2 Wiki 与文档基础](knowledge-m2.md)。

本文记录 M3 阶段的交付和验证结果。M3 提供 Embedding 设置、独立凭据入口、连接测试、手动构建、持久化向量缓存、取消和手动续作。当前版本已接入 [M4 混合检索](knowledge-m4.md)：默认关闭；保存配置、打开设置、发现工程和基础查询都不会调用 Embedding。启用且有兼容索引后，`project_context` 可生成当前问题向量，单独计量；普通聊天不重建文档向量。

## 使用方式

1. 在当前 DSH 对话的 Unreal Editor 面板绑定 UE 工程；DSH 工作区不决定知识库归属。`unreal_knowledge_projects` 返回当前绑定工程。
2. 在 Unreal Bridge 官方设置页的“知识库”页签填写服务地址与模型，启用后点击上方“保存设置”。配置名称、维度和请求限额放在“高级参数”中。切换页签保留草稿；未保存草稿或版本冲突期间不能启动测试或构建。
3. 在下方独立密码输入框保存 API Key。输入框保存后清空；公开配置和状态只显示是否已配置，不回显密钥。
4. 在“凭据与连接”中点击“测试连接”：发送一条固定短文本，恰好一次请求，不发送工程资料，可能计费。测试期间显示等待状态，成功显示绿色文字，失败显示红色原因；失败不自动重试。功能未启用、配置未保存或缺少 Key 时，显示按钮不可用的原因。
5. 设置页自动显示当前对话绑定的 UE 工程、`ProjectKnowledge` 和插件 `Cache` 完整路径。将知识文件放入 `ProjectKnowledge` 后，点击“生成/更新向量索引”。不再提供项目或目录选择；切换对话或绑定后刷新归属，旧绑定的操作会被拒绝。
6. 任务返回后显示阶段、文档/片段数、独立输入数、缓存命中、失败数、请求次数和服务返回的 Token 用量。页面仅轮询状态，不重复提交。收费以服务商账单为准。

“重建向量索引”重建当前映射和发布版本，仍复用有效缓存；“更新基础索引”只更新全文和源码图谱，零 Embedding 请求。基础构建发布新 generation 后，旧向量映射不再作为当前索引；再点击生成可复用仍匹配的缓存。

排除规则继续由工程 `ProjectMemory.project.json` 控制。只有 `ProjectKnowledge` 中符合策略的已解析片段被发送，不默认向量化整个源码库或 UE 资产。实际文档规模在扫描完成后显示，任务具有请求数和时间上限。

## 服务协议与限制

首版支持 OpenAI 兼容 `POST /embeddings`，请求包含 `model`、字符串数组 `input` 和 `encoding_format: float`。Base URL 自动追加一次 `/embeddings`，完整 endpoint 不重复追加。要求 HTTPS，本机 `localhost/127.0.0.1/::1` 可用 HTTP；拒绝 URL 内凭据、查询参数、片段和聊天 endpoint，不跟随重定向。

返回的 `data` 数量、`index` 唯一性、维度、有限数值和非零范数必须有效。允许返回数组乱序，但按 `index` 还原。向量统一保存为 L2 归一化 Float32。失败响应最多读取 32 KiB 来识别错误类别；服务原始错误正文不进入日志或界面，避免回显 Key 或上传资料。只记录本地生成的原因、HTTP 状态、有限格式的服务错误码/请求编号、尝试次数与输入数量。

失败信息区分超时、网络中断、每批数量超限、文本长度超限、输出维度、模型/接口、Key/权限、余额/免费额度、请求频率和服务端异常，并显示对应设置或恢复步骤。阿里云 `text-embedding-v3/v4` 的每批 10 条限制会在生成前校验；单条连接测试通过不代表批量配置也满足服务限额。

任务失败时显示失败环节、已保留向量数、剩余数量和直接续作按钮。改过配置时应使用“生成/更新向量索引”，模型空间与输入一致的缓存仍可复用。旧版本曾将真实 Fetch 的数值型超时错误码错误地当作字符串处理，再误报为 `CANCELLED`；已修正类型检查，并在停止其他并发请求前保留首个失败原因。旧记录缺少的原始原因无法补回，界面会标记为原因未记录，不推断为用户手动取消。

| 设置 | 默认值 | 范围/行为 |
| --- | --- | --- |
| 输出维度 | 0 | 0 表示从返回值确认；1～8192 显式发送 `dimensions`，服务须支持 |
| 每批片段 | 10 | 1～128；每批另限 128000 个 UTF-16 字符 |
| 同时请求 | 2 | 每任务 1～4；每个宿主最多两个向量任务 |
| 单片段输入字符 | 16000 | 128～64000，包含标题；超过即停止，不截断正文 |
| 请求超时 | 30 秒 | 1～120 秒；429、临时服务/网络错误最多重试两次 |
| 任务请求上限 | 1000 | 1～10000，包含重试，每次手动续作重新计量 |
| 任务总时限 | 30 分钟 | 1 秒～120 分钟；到时停止，等待手动续作 |

401/403、模型或维度不支持、无效响应不重试；重试退避有界，单次最多等 5 秒。单次响应最多 32 MiB，单任务最多 50000 片段、64 Mi 个独立输入字符。字符限额不等于模型 Token 限额，应按服务能力设置。

## 凭据

优先使用已验证的 DSH `credentials.readRecord/describeRecord/modifyRecord/deleteRecord`，记录类型为 `api-key`。密钥记录由 `profileId + 规范化 endpoint` 定位；换服务地址需要为新地址保存对应 Key。配置名称是凭据分组，不是同时启用多个模型的配置列表。

真实 DSH 0.2.2-rc.5 的本地凭据提供者已通过临时配置验证。该提供者由 DSH 管理，**不宣称加密保存**。缺少记录接口的 Windows 宿主使用 DPAPI CurrentUser：加密内容保存在 `stateDir/EmbeddingCredentials/`，只能由对应 Windows 用户解密。隐藏的固定 PowerShell 助手通过 stdin 接收密钥，不把密钥放进命令参数。其他平台若缺少宿主凭据服务，则明确拒绝保存，不使用明文回退。

密钥不进入官方 Config、工程文件、任务 JSON、向量库、manifest、公开状态、UE 通信或普通模型工具。配置/凭据变化会取消进行中的测试与未发布任务；扫描完成、发送前和发布前再次校验配置、工程策略及凭据。

## 缓存、恢复与发布

实际输入模板 `title-section-text-v1` 为：

```text
Title: <文档标题>
Section: <标题路径>

<片段原文>
```

缓存由实际输入 SHA-256 与向量空间共同定位。空间包括协议、规范化 endpoint、模型名、请求维度、输入模板版本及归一化版本；实际返回维度另外固定到空间记录。换 Key 或批量/并发设置不会强制重算；换模型、维度或模板不会混用旧向量。同内容的不同文档共用计算结果，保留各自 `documentId/chunkId/sourceHash` 引用。服务端模型内容变化但名称/维度不变无法自动识别，应使用固定模型版本。

向量缓存为工程内 `Plugins/DSHUnrealBridge/Cache/Knowledge/<projectId>/embedding/vectors.sqlite`，任务在同级 `embedding/jobs/`。旧 DSH 状态目录中的知识缓存首次访问时复制迁移，原件保留；不会覆盖已有目标缓存或自动重建。不同 DSH 对话共享同一工程缓存。不依赖 sqlite-vec 或额外 DLL；SQLite 和向量计算在独立 Worker 中加载。当前查询原语使用有界精确余弦扫描，尚未宣称真实大型工程的性能指标。

构建与 M1 基础任务共用项目锁，查询继续读取完整的旧版本。每批成功结果先事务落盘，再创建新的文档、全文、图谱和向量 generation。向量映射位于 `Memory/index/vector.sqlite`，元信息位于 `vector-manifest.json`；核对来源及工程描述符后仅替换一个 `current.json` 指针。失败、取消或来源变化均不发布半成品。

取消停止后续批次，已经提交的请求仍可能计费。退出宿主会停止任务；异常退出记录显示为中断，不自动恢复。用户点击“继续未完成任务”后使用新的请求 ID，校验原配置和工程策略并重新扫描来源，只补算缓存缺失部分。任务显示本次与此前请求次数，持久化两段 Token 用量。重复请求 ID 返回同一任务；参数不同则拒绝。

缓存条目校验失败会视为缺失。手动构建遇到可识别的 SQLite 文件损坏时保留 `.corrupt-<UUID>` 文件并重建缓存，可能重新计费，状态显示恢复标记。权限、磁盘错误不会被当作损坏自动忽略。已发布向量损坏不会影响基础查询；显式构建可重建映射。索引与旧 generation 目前不自动清理。

## 接口

全局 Remote 提供 `embeddingStatus`、`embeddingSetCredential`、`embeddingRemoveCredential`、`embeddingTest`、`embeddingBuild`、`embeddingCancel`、`embeddingResume`。操作通过严格 schema 校验，不注册为模型工具。

- 状态可不带工程；工程任务必须携带已登记的 `projectHandle`。
- 保存/移除 Key、测试、构建和续作携带已保存配置的 `configFingerprint`。
- 测试、构建、续作使用 UUID `requestId`；取消使用 `jobId`。
- 构建包含 `roots` 与 `mode: update | rebuild`。
- M3 阶段能力为 `dsh_embedding_index_v1`，当时返回 `retrievalMode: base`、`integration: index_management`。M4 另增检索能力与查询用量，当前字段见 [M4](knowledge-m4.md)。

## 验证

`npm run check` 覆盖全部宿主回归和 19 项 M3 后端/界面专项；本机 HTTP 模拟服务使用假 Key，验证默认零调用、固定文本测试、重复输入去重、未变零调用、修改/删除、空间隔离、限额、重试、取消/续作、异常退出记录、两项目并发、来源变化、缓存损坏、凭据与界面项目切换。

`scripts/settings-runtime-check.mjs` 使用真实 DSH Loader、Settings、ConfigEditor、原生凭据服务和工具执行器，在临时 profile 中验证字符串/选择字段、版本冲突、密钥保存/重启恢复/移除及旧执行保护。兼容当前批量工具执行接口与旧执行入口；不修改已安装的用户 profile。

发行包通过 `npm run package:dsh` 生成。解包后将 `DSH_EMBEDDING_TEST_PACKAGE` 设为 `package` 目录，再运行 `node --test test/embedding.test.mjs`，同一套测试直接加载包内 `knowledge-worker.js` 与 `embedding-worker.js`，验证独立构建、缓存、续作及引用回读。

最终结果：宿主测试 **434/434**、知识工具 **59/59**、真实 DSH 临时配置检查 **9/9** 通过；实际 tgz 的两个 Worker 在 Node **24.15.0** 和已安装 DSH/Electron 的 Node **24.21.0** 上分别通过 **14/14** 项测试，解包宿主也通过 9 项真实运行时检查。发行包含五个 JS 文件，无 sourcemap；`git diff --check` 通过。其他受支持 Node 版本与完整安装矩阵仍由 M5 验证。

未使用真实付费服务或真实用户密钥，未运行 UE 联调，未安装/重启用户插件。PDF/OCR 仍按独立阶段交付。
